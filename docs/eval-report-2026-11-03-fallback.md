## 0. 结论

1. **L0 上，新模式的回答正确率提升了。** F-new vs F-filter 的回答正确率是 0.880 → 0.930，95% CI [+0.007, +0.100]，判为「提升」。逐题看，8 道题变好，2 道题变差（q027、q030）。变好的 8 道题里，4 道是 F-filter 误拒的题（q012、q031、q034、q039），2 道是 F-new 用模型知识兜底的题（q035、q037，见第 5 节）。
2. **L1 上，回答正确率的提升不显著。** F-new-L1 vs F-filter-L1 是 0.853 → 0.910，95% CI [0.000, +0.120]，判为「持平」。CI 的下限正好是 0，所以不能写「提升」。
3. **拒答题上，新模式每次都给出了「找不到」提示。** F-new 是 10/10（3 次都是），F-new-L1 是 5/5（3 次都是）。F-filter 和 F-filter-L1 在这些题上都是拒答（10/10、5/5）。
4. **误拒少了，但「找不到」的误报还在。** F-filter 每次误拒 3/50、3/50、4/50。F-new 没有拒答，但每次有 2/50 道可回答题以固定句开头（q031、q034）。L1 上，F-filter-L1 每次误拒 6/50，F-new-L1 每次有 5/50、5/50、4/50 道可回答题以固定句开头。
5. **说了「找不到」的可回答题，大多数最后还是有用的。** F-new 的 6 个这样的回答里，4 个是 correct 或 partial。F-new-L1 的 14 个里，11 个是 correct 或 partial。答错的 3 个都是 q034（第 4.2 节）。
6. **只看笔记里有答案的题，Faithfulness 没有变化。** 在两边都没有说「找不到」、也没有拒答的可回答题上，L0 是 0.958 → 0.947（n=46），L1 是 0.975 → 0.980（n=44），两组都判为「持平」。如果把全部 50 道可回答题都算进去，L0 的 Faithfulness 判为「下降」（0.955 → 0.904）。原因是兜底回答本来就不依据检索片段。
7. **模型不总是用完整的固定句。** 有一部分兜底回答写成「笔记里没有找到直接讨论……的内容。」。`is_not_found()` 只认完整的固定句，所以判不出这些回答。按「以 `笔记里没有找到` 开头」重新数，L0 每次多 2–3 道，L1 每次多 2 道（第 5 节）。所以第 4 条的误报数是下限。
8. **费用：** 12 次有效的正式运行花了 $2.63，smoke 花了 $0.06，上限是 $5。

## 4. 回答示例

### 4.1 F-new 在拒答题上的回答（第 1 次运行）

10 道拒答题在 3 次运行里都以固定句开头，然后用模型知识回答。下面是 3 个例子，原文照录。

**q052：Corrective RAG（CRAG）中，检索评估器判断检索结果质量差时会采取什么动作？**

> 笔记里没有找到相关内容。根据我的知识，CRAG 的检索评估器会把检索结果分为正确、错误、模糊三档；判定为质量差（错误）时，会丢弃检索结果，转而触发网络搜索获取新资料，并对结果做分解与筛选后再生成。

**q053：RoPE（旋转位置编码）是如何把相对位置信息注入注意力计算的？**

> 笔记里没有找到相关内容。RoPE 通过旋转矩阵对 query 和 key 向量进行变换：将向量按维度两两分组，每组根据其位置乘以不同频率的旋转角，使 q 与 k 的内积只依赖二者的相对位置差，从而在注意力计算中注入相对位置信息。

**q055：GQA（Grouped-Query Attention）相比 Multi-Head Attention，如何减少推理时的显存占用？**

> 笔记里没有找到相关内容。根据我的知识：GQA 让多个 Query 头共享同一组 Key/Value 头，从而大幅减少 KV Cache 的存储量——推理时 KV Cache 是显存占用的主要来源之一，共享后需要缓存的 K/V 数量成倍下降，显存占用随之降低，同时性能接近 MHA 而远好于 MQA。

注意：拒答题没有参考答案，所以评审模型没有给兜底部分打正确率分。我读了这 3 个回答，内容和公开论文的描述一致，但这不是系统的检查。

## 5. 固定句的变体

模型写兜底回答时，有时不用完整的固定句。常见的写法是「笔记里没有找到直接讨论“……”的内容。」，后面再用模型知识回答。

| | L0（F-new） | L1（F-new-L1） |
|---|---|---|
| 可回答题：完整固定句（`is_not_found()`） | 2、2、2 | 5、5、4 |
| 可回答题：以 `笔记里没有找到` 开头 | 5、4、4 | 7、7、7 |
| 多出来的题 | q035、q037、q039 | q033（第 3 次）、q036、q038 |
| 多出来的回答的正确率 | 7 个里 7 个是 correct 或 partial | 7 个里 6 个是 correct 或 partial |

- 10 道拒答题（L1 上 5 道）每次都是完整固定句，所以「找不到」提示率不受影响。
- 受影响的是可回答题上的误报数：第 2.1 节的误报数是下限。
- 这些变体回答留在了 `answerable_found` 题集里的有 q035、q037（L0）和 q036（L1）。去掉它们后，Faithfulness 的结论不变：L0 是 -0.006，95% CI [-0.024, +0.010]，n=44；L1 是 +0.002，95% CI [-0.007, +0.012]，n=43，两组都是「持平」。数据在 `backend/evaluation/results/stats/fallback_broad_not_found.json`。
- F1 的手动测试里，QA 智能体路径上也出现了这个问题（3 次里 2 次是变体）。如果线上要靠固定句识别「找不到」（例如在界面上加标记），需要另外处理，例如把判断改成前缀匹配，或者在后处理里统一改写第一句。本任务没有改。

## 6. 测量的局限

1. 回答正确率由 Haiku 评分。L1 任务里，Opus 校准的 Spearman 是 0.945，但那次校准没有覆盖兜底回答。评审模型有时把固定句当成「与后文矛盾」来扣分（例如 q035、q040 的评审理由），所以兜底回答的分数可能偏低。
2. 拒答题上的兜底内容没有参考答案，没有打正确率分（第 4.1 节）。
3. 12 次运行全部在 DeepSeek 高峰期，P95 受拥堵影响，不能用来比较（第 2.1 节）。
4. 只测了评测管线（`eval_rag.py`），没有测 QA 智能体路径。任务文档 v0.2 把智能体路径的评估去掉了。
5. 固定句判断只认完整的句子，误报数是下限（第 5 节）。
